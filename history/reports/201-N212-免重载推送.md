# 201 / N212 — 免重载推送：`unbind/bind` 就够，不必 rmmod nvidia

日期：2026-10-29 10:34–10:50
设备：P104-100（10de:1b87），Debian 13 / kernel 6.12.113+deb13-amd64 / NVRM 580.178.04

---

## 0. 结论

**用户的方案成立。** 补丁早在 `.ko` 里时（例如重启后），完全不需要重载 nvidia：

```bash
sudo insmod build/gen2kr.ko
echo 0000:01:00.0 | sudo tee /sys/bus/pci/drivers/nvidia/unbind
echo 0000:01:00.0 | sudo tee /sys/bus/pci/drivers/nvidia/bind
```

实测结果：链路 5GT/s、pinned **H2D 1.561 / D2H 1.708 GB/s**、**nvidia 全程未被卸载/重载**。

### 判据：什么时候必须重载

| 场景 | 要重载吗 | 原因 |
|---|---|---|
| 刚 `patch_no_gen1.py apply`（`.ko` 变了） | **要** | 不重载内核跑的还是旧代码 |
| 重启后（补丁早在 `.ko` 里） | **不要** | 只需让设备重新 probe 一次 |
| 补丁丢失后重新 apply | **要** | 同上 |

`20-install.sh` 已改为自动判断（比对 apply 前后 md5），并支持 `--no-reload`。

## 1. 为什么 `unbind/bind` 就够

gen2kr 的推送时机是 **`nv_pci_probe` 返回的瞬间**（kretprobe）。
而 `unbind` + `bind` 正是**手动触发一次完整的 probe 周期** ——
它调用的就是同一个 `nv_pci_probe`，所以 kretprobe 照样命中。

重载整个 nvidia 模块是"更重"的做法，只是在"补丁文件变了"时**必须**做
（内核里已加载的代码不会因为文件变了而更新）。

### 实测日志
```
[  598.184487] gen2kr: nvidia refcnt 基线 = 1
[  598.184506] gen2kr: 预映射 BAR0 @ f6000000 -> ffffd0eb0b000000
[  598.187234] gen2kr: 已在 nv_pci_probe 上挂 kretprobe
[  599.806259] gen2kr: [fast] 直接写 SPEED=1，原 20045800 → 20045800
[  599.806265] gen2kr: nv_pci_probe 已返回，已排队重训
[  599.806281] gen2kr: [push] 起始 cap2=00000006 config=c0b48d00 lnkcfg0=20045800
[  599.806289] gen2kr: [push] 写完 cap2=00000006 config=c0b4ad00 lnkcfg0=20045800 cya=068711b3
[  599.860583] gen2kr: 端点 TLS2 0002 -> 0002
[  599.860599] gen2kr: 根端口 TLS2 0042 -> 0042
[  599.860601] gen2kr: 根端口 LNKCTL 0040 -> 0060 (Retrain)
[  599.964623] gen2kr: ★ SUCCESS Gen2 LNKSTA=1042（第 1 次）
```

### 一个值得注意的细节
`[push] 起始 config=c0b48d00` —— 这是**未解锁**值（解锁后应为 `c0b4ad00`）。
说明 `unbind` 确实把 `0x8841C` 的 bit15/13/11 清掉了。

但 `push_fn` 每次都会重写整套解锁序列（`写完 config=c0b4ad00`），
**所以完全不依赖残留状态**。这反而是好事：每次 push 都是干净的。

## 2. ★ 修正 reports/198 的一个观察

reports/198 §7 记录过「驱动 reload 后会把端点声明重置回 Gen1」：

```
LnkCap = 0x00453c41  MaxSpeed=1
LnkCap2 = 0x00000002  vector=0x02（仅 Gen1）
LnkCtl2 = 0x0001      TLS=1
```

**本次实测否证了这个说法的一般性。** 单纯 `rmmod nvidia && modprobe nvidia` 之后：

```
LnkCap  = 0x00454c42   MaxSpeed=2      ← 仍是 Gen2
LnkCap2 = 0x00000006                   ← 仍解锁
LnkCtl2 = 0x0002       TLS=2
0x8841C = 0xc0b48d00                   ← 解锁位仍置位
链路    = Speed 5GT/s
```

⇒ **reload 不会复位声明。** reports/198 当时看到的 Gen1 状态，
应该是那一轮做过的**总线复位**（`reset_subordinate` 等）造成的，不是 reload。

### 三者的区别（实测）

| 操作 | `0x8841C` 解锁位 | `LCAP2` | 链路 |
|---|---|---|---|
| `unbind` + `bind` | **被清**（`ad00` → `8d00`） | 保持 `0x0006` | 保持 Gen2 |
| `rmmod` + `modprobe` | **保持解锁** | 保持 `0x0006` | 保持 Gen2 |
| 整机断电 | 复位 | 复位 `0x0002` | 复位 Gen1 |

**实用推论**：
- 想把状态复位到原厂做测试 ⇒ **只能整机重启**（`rmmod/modprobe` 无效）
- 每次 `unbind/bind` 会清 `0x8841C`，但 push 会重写，无需担心

## 3. 代码改动

### 新增 `bin/push.sh`
轻量推送，专做 `insmod` + `unbind/bind`：
- 前置检查：nvidia 已加载 + 补丁在位
- 若 gen2kr 已在内存里，先 `rmmod` 再 `insmod`（**清掉 `triggered` 标志**，
  否则 push 不会再触发 —— 这是个容易漏的细节）
- 等链路到 Gen2（最多 20s），失败时打印 dmesg 并提示排查

### `bin/20-install.sh` 改为自动判断
```
BEFORE="$(md5sum "$KO")"
apply
AFTER="$(md5sum "$KO")"
if [ "$BEFORE" != "$AFTER" ]; then PATCH_CHANGED=1; fi
```
- `PATCH_CHANGED=1` ⇒ 进"重载"分支
- 否则 ⇒ 进"不重载，只 push"分支
- 新增 `--no-reload` 强制走轻量路径

两个方向都实测过：

| 场景 | 输出 |
|---|---|
| 补丁已在 | `✓ 补丁本来就在（.ko 未变）⇒ 不需要重载` / `=== 2. 不重载 nvidia ===` / `✓ nvidia 保持加载中` |
| revert 后重新 apply | `✓ 补丁是新写入的 ⇒ 需要重载 nvidia 才生效` / `=== 2. 重载 nvidia 驱动 ===` / `✓ 已卸干净` |

另外修了一个隐患：原步骤 3 直接 `insmod`，若 gen2kr 已在内存里会报 `File exists`
且 `triggered` 标志是旧值（push 不会触发）。现改为先 `rmmod` 再 `insmod`。

## 4. 当前推荐用法

### 首次 / 补丁刚变更
```bash
sudo bash bin/20-install.sh
```
（自动：apply → 判断要不要重载 → 重载 → push）

### 日常（重启后 / 需要重新推送时）
```bash
sudo bash bin/push.sh
```
约 3 秒，不碰 nvidia。

### 手动等价命令（不依赖脚本）
```bash
sudo insmod /data/labs/nvidia/nvidia-p104-unlock-gen2-for-linux/build/gen2kr.ko
sudo sh -c 'echo 0000:01:00.0 > /sys/bus/pci/drivers/nvidia/unbind; sleep 1; \
            echo 0000:01:00.0 > /sys/bus/pci/drivers/nvidia/bind'
sudo python3 bin/peek-regs.py            # LNKSTA CurSpeed=2
build/bwtest2 512 15 | grep pinned       # ~1.56/1.71
```

## 5. 用户原问题的直接回答

### Q1：补丁过的驱动能不能正常加载？
**能。** 本轮多次 `rmmod` / `modprobe`（含 revert→apply 后重载），全部正常，
无报错、无 Xid、`NVRM version: 580.178.04` 正常打印。补丁只改 2 个立即数，
不触碰模块结构（`.modinfo` / 符号表 / 重定位），加载器无感知。

### Q2：不想重载 nvidia，能不能完成 push？
**能，且已实测。** 见 §0/§1。`unbind/bind` 触发的是同一个 `nv_pci_probe`。
