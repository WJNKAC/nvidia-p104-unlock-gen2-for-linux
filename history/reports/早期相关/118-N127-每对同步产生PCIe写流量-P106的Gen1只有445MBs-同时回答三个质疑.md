# 报告 118 / N127：**每对同步 = 一次 PCIe 写入；P106 的 Gen1 只有 445 MB/s** —— 同时回答你的三个质疑

- 时间：2026-10-26 22:10
- 环境：union@192.168.1.43（`Portable`），525.116.03，P106-100
- 触发：用户「有输出的 Pascal 卡也应该受影响，但社区反馈与此矛盾」
- 性质：**新证据（dmon 实测 PCIe 流量）+ 修正上一轮**

## 0. 关键新证据：dmon 直接看到了 PCIe 流量

```
M1 只 draw 300（0 次同步）    sm=0%    PCIe rx=0   tx=0 MB/s
M9 切 300 再画 300（1 次同步）  sm=0%    PCIe rx=0   tx=0 MB/s
M3 交替 300（300 次同步）       sm=99%   PCIe rx=13  tx=445 MB/s
M6 交替同 prog（300 次同步）    sm=99%   PCIe rx=11  tx=445 MB/s（三次采样一致）
```

**⇒ "每对同步"与 "PCIe 写流量" 一一对应，且只在同步时出现。**
**⇒ M1/M9 的 tx 精确为 0 —— 这是干净的对照。**

### 0.1 换算

```
445 MB/s ÷ (1e6/121µs) = 445e6 ÷ 8264 对/秒 = 53,845 B ≈ 52.6 KB / 对
反算：52.6 KB ÷ 445 MB/s = 121.0 µs        ← 吻合
```

> ⚠️ **诚实标注**："52.6 KB" 是**反算值**（用实测 445 MB/s 和实测 121 µs 相除），
> **不是独立测量**。独立的部分只有两条：「同步时产生 445 MB/s」「不同步时 0」。
> 但这两条已经足够定位机制。

## 1. 这个模型一次回答你的三个质疑

| 你的质疑 | 本模型给出的回答 |
|---|---|
| **515 也过同一条 Gen1 PCIe，为什么它 0.03 µs？** | **515 不产生这 52 KB 的 PCIe 写**（M1/M9 证明了"不同步 = 0 流量"）。带宽只在有流量时才起作用 —— 没有流量，Gen1 再慢也无所谓。 |
| **vGPU 的物理 GPU 也在宿主上，宿主也过 PCIe，为什么快？** | guest 侧那 52 KB 写到的是**宿主 DRAM**（`remap_pfn_range` 映射），**不过 guest 的 PCIe**。宿主自己的 PCIe 流量是另一条路径，不在 guest 的关键路径上。 |
| **有输出的 Pascal 卡也该受影响，但社区没有** | **它们也传同样的 52 KB，但它们是 Gen3。** 445 MB/s × 8 ≈ 3.5 GB/s ⇒ 每对 **15 µs** ⇒ 268 对/帧 = **4.1 ms**，在 60 fps（16.7 ms）预算里完全够用，**不显眼**。 |

### 1.1 这就是"只有 P106 有问题"的完整解释

| 卡 | Gen | 每对 | 268 对/帧 | 是否显眼 |
|---|---|---|---|---|
| **P106-100** | **Gen1 / 445 MB/s** | **121 µs** | **32.4 ms** | **致命（30 fps）** |
| GTX 1080 / P4000 | Gen3 / ~3.5 GB/s（推算） | ~15 µs（推算） | ~4.1 ms | 不显眼 |
| 515 驱动的 P106 | 不传这 52 KB | 0.03 µs | ~0 | 无 |
| vGPU 里的 P106 | 传入宿主内存 | ~0 | ~0 | 无 |

**⇒ 不是"只有 P106 触发"，而是"所有卡都传，但只有 Gen1 慢到能看出来"。**
**⇒ P106 是挖矿卡，PCIe 被砍到 Gen1（`Link Cap` 只读字段 = 0x1），这才是它独有的短板。**

## 2. 这条证据同时修好了上一轮的两处错

### 2.1 撤回"PCIe 不是根因"

报告 117 我说 PCIe 不是根因，因为"515 也过同一条 PCIe"。
**那个推理的错处是：把"带宽"当成了"只要有 PCIe 就收费"**。

**正确的表述**：**PCIe 带宽只在有流量时才成为成本；515 没有这个流量。**

### 2.2 撤回"GPU 全局串行化"

报告 117 我用双进程实验证明"总吞吐恒定 ⇒ GPU 全局串行资源"，推向了 ctxsw。

**现在这个数据有了更好的解释**：**PCIe 链路是全局的**。
两个进程各自要写 52 KB/对，共享同一条 445 MB/s 的 Gen1 链路 ⇒ **总带宽被均分 ⇒ 每个进程速率减半、总吞吐恒定。**

**⇒ 双进程实验的证据完全成立，但归属应该是"共享 PCIe 链路"，不是"GPU ctxsw"。**

这反而更自然：链路是物理上唯一的，两个进程按时间片分享它。

### 2.3 ctxsw 假说被你的质疑杀死

如果真是 ctxsw，**GTX 1080 也该慢**（Pascal 的 ctxsw 一样贵）。
但社区没有这个反馈。

**⇒ ctxsw 假说正式作废。**
**⇒ 而且 445 MB/s 的 PCIe 流量是直接观测到的，比"推断有 ctxsw"硬得多。**

## 3. 为什么"与状态类型无关"也说得通

| 状态类型 | 每对 |
|---|---|
| 切 program | 123.4 µs |
| 切 FBO | 123.5 µs |
| 切 texture | 126.0 µs |
| legacy 4 状态 | 126.0 µs |
| uniform | **4.5 µs（免费）** |

**如果是"每对不同状态都重传一份固定大小的状态块"，那么：**
- 换哪种对象都一样（都是重传同一块）→ 解释三种同成本
- uniform 改变的是内联在 pushbuffer 里的值，不触发状态块重传 → 解释免费

**⇒ 与"重传一个固定大小的状态块"完全一致。**

## 7. 一句话

**你说得对，ctxsw 解释不了"有输出的 Pascal 不受影响"—— 那条假说作废。**
**新的直接观测是：`dmon` 显示 M3 有 445 MB/s 的 PCIe 写，而 M1/M9 精确为 0。**
**⇒ 每对"状态变更+draw"要往显存写约 52 KB（反算），P106 的 Gen1 只有 445 MB/s ⇒ 121 µs/对 ⇒ 268 对 = 32.4 ms ⇒ 30 fps。**
**⇒ GTX 1080 是 Gen3，同样 52 KB 只要约 15 µs，268 对 = 4.1 ms，在 60 fps 预算内 —— 所以社区看不到问题。**
**⇒ 515 不产生这个流量（M1/M9 已证明"不同步=0"），所以它不受 Gen1 影响。**
**⇒ vGPU 把这 52 KB 写进宿主 DRAM，不过 guest 的 PCIe。**
**"只有 P106 有问题"不是因为它特殊，而是因为它是唯一一款把 PCIe 砍到 Gen1 的卡。**
