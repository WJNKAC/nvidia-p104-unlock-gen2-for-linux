# 复现方案复盘：与参考项目逐项对照

**日期**：2026-10-28
**参考**：`github.com/skbskhud/p104-gen2-unlock`（Windows，P104-100，Gen1 x4 → Gen2 x4，实测 0.78→1.55 GB/s）
**本机**：P104-100 `10DE:1B87` rev a1，VBIOS `86.04.7A.00.19`，Linux 6.12.113 + 驱动 580.178.04

## 1. 参考项目的完整方案（两份文档合并后）

### 工具做的 5 件事（`docs/02-工具说明.md` 第 21-26 行）

| # | 动作 | 实现方式（Windows） |
|---|---|---|
| 1 | 读写 BAR0 与 PCI 配置空间 | 两个内核驱动 `WinRing0x64.sys` + `ThrottleStop.sys` |
| 2 | PnP 禁用 → 启用 | 设备管理器级操作（驱动卸载 + 设备 D3 + 重新枚举） |
| 3 | 写注册表策略 | `RMPcieLinkSpeed` 等，与 NVIDIA 驱动策略同名 |
| 4 | 常驻进程 20ms 重写 | "按住"是必需的 |
| 5 | 开机自启计划任务 | 名 `P104 PCIe Gen2x4 Bring-up` |

### 技术报告 §3.2 的五步（`docs/01-技术报告.md` 第 116-148 行）

| 步 | 内容 |
|---|---|
| 1 | `0x8E110=1`、`0x8E11C=4`、`0x8E120=0`、`0x8E12C=0x200000`；`0x8841C` 置 bit11/13 清 bit12/14；`0x88610` 清 bit12 置 bit0；`0x8872C=6`；`0x8C040` SPEED[19:18]=1 + COMMIT |
| 2 | PnP 禁用 → 启用 |
| 3 | 等 ≥ 25 秒（等驱动重新绑定并读注册表策略） |
| 4 | 两端（GPU + 根端口）设目标速率 = 2，交替重训 |
| 5 | 常驻按住 20ms（不可省，否则掉回 Gen1） |

**关键引文**（01 第 162-164 行）：
> 真正起作用的不是单次写入，而是「写请求 → 重新初始化 → 等锁存 → 按住」这一整套时序。
> 这也解释了为什么手工试一次通常失败。

## 2. 我们的 Linux 映射（哪些等价、哪些不等价）

| 他的动作 | 我们的映射 | 等价性 | 备注 |
|---|---|---|---|
| WinRing0 驱动读写 BAR0 | **`/dev/mem` mmap**（需 `iomem=relaxed`） | ✅ 等价 | sysfs `resource0` mmap 在本机返回 EINVAL |
| WinRing0 读写 config space | `setpci` | ✅ 等价 | 但相关字段全部 RO（两卡实测） |
| **PnP 禁用 → 启用** | 试过 4 种：<br>① `unbind/bind`<br>② PCI reset（`echo 1 > reset`）<br>③ `enable 0/1`<br>④ `remove`+`rescan` | ❌ **没有一个完全等价** | ①不够（硬件不重新初始化）<br>②③④都会清掉 `0x8841C`（bit15 丢失）或直接失败（③ EIO/EBUSY） |
| **注册表策略** | `NVreg_RegistryDwords="RMPcieLinkSpeed=2"` | ⚠ 名字相同，**效果未证实** | `/proc/driver/nvidia/params` 确认已传入驱动；但 Linux RM 是否认这个键未知 |
| 等 25 秒 | `sleep 25` | ✅ | 但策略未生效时等了也没用 |
| 两端设速率 | GPU 端 `LNKCTL2`（被钳）+ 根端口 `setpci`（可写） | ⚠ 半等价 | 根端口可写但没推动链路 |
| 按住 20ms | Python 循环 400 次/8 秒 | ✅ 等价 | 声明能维持，链路不动 |

## 3. 五轮尝试时间线

| 轮 | 做了什么 | 结果 | 学到什么 |
|---|---|---|---|
| 1 | 只写 `0x8C040`（SPEED+COMMIT），**无覆盖槽** | 💥 立即掉卡 | `0x8C040` 有前置条件 |
| 2 | 完整配方第一版：覆盖槽 + `0x8841C`(bit15) + `0x2241C=0x80` + unbind/bind + 等 25s + 两端设速率 | 💥 第 4 步掉卡（443s RmInitAdapter failed） | 覆盖槽有效（`0x8C040` 写入不再立即崩）；但 `0x2241C` 少了 bit0 |
| 3 | `NVreg_RegistryDwords="RMPcieLinkSpeed=2"` + 重载；`enable 0/1` | 策略进驱动 ✓；`enable 0` 报 EIO | 发现 `nvidia-smi --gpu-reset` 是对的复位方式 |
| 4 | `0x88610=1` → **VER=2**；`LNKCTL2=2` **可写**；然后 `0x8C040` | 💥 第四次掉卡 | **握住 L 状态**（VER/CAP2/LNKCTL2 全对） |
| 5 | 六项状态全对 + **按住 8 秒**（400 次重写） | 链路仍 Gen1；**停止按住后声明回退** | 证据链闭合：声明层全可改，PHY 不动 |

## 5. 仍未解的四个疑点

| # | 疑点 | 影响 |
|---|---|---|
| 1 | **Linux 上没有 PnP 禁用/启用的精确等价物**。四种尝试要么不触发硬件初始化（unbind/bind），要么清掉 `0x8841C`（PCI reset / remove+rescan），要么直接失败（enable EIO/EBUSY） | 可能是全部失败的根源——声明锁存需要"正确的复位方式" |
| 2 | `RMPcieLinkSpeed=2` 已进驱动参数，**但 Linux RM 是否消费这个键未验证**。Windows 是写注册表让驱动读；Linux 的 `RegistryDwords` 键空间可能不同 | 如果 Linux 不认，驱动永远不会按 Gen2 初始化 |
| 3 | 本机 `0x8C040` Gen1 值 `0x20085800` 与参考项目 `0x20585800` 差 **bit20+bit22**，语义未知 | 如果这两位是必需的链路参数，我们写入 SPEED 时缺它们 → 崩溃 |
| 4 | 他的卡与我们**同为 P104-100 同 VBIOS**，但他成功我们失败 | 要么批次差异（PHY 能力），要么他的"复位"方式在 Linux 上没有精确等价物 |

---

## 6. 最终结论

**声明层（① 寄存器层）我们已经完全打通：**
六项状态 5/6 达成，其中 `VER=2`、`LNKCTL2=2`、`CAP2=0x06` 都是本轮新突破。

**链路层（PHY）不动：**
五种触发方式、按住 8 秒 400 次施压、全部无效。

**最诚实的结论**：

> 参考项目证明 Gen2 在寄存器层可解（① 层）。我们把 ① 层能做的都做了，
> 声明也对上了，但**链路没有切换**。剩下的差距集中在两个未解疑点：
> **Linux 上 PnP 复位的精确等价物**（疑点 1）和 **`RMPcieLinkSpeed` 在 Linux RM 里的有效性**（疑点 2）。
> 这两个都不是"再试几次"能解决的——需要弄清 Windows PnP 复位的确切语义，
> 或者在 Linux RM 源码里确认 `RMPcieLinkSpeed` 的消费路径。

**当前系统状态**：GPU 功能正常（Gen1 x4，57.8W），`iomem=relaxed` 仍在生效，
`/etc/modprobe.d/nvidia-gen2.conf` 里 `RMPcieLinkSpeed=2` 策略仍在（重启后自动加载）。
