# PCIe Gen2 解锁实验记录（P104-100，Linux）

**日期**：2026-10-28
**卡**：NVIDIA P104-100 `10DE:1B87` rev a1，VBIOS `86.04.7A.00.19`
**系统**：Debian 13，kernel 6.12.113，驱动 580.178.04，显示走 Intel 核显
**参考**：`github.com/skbskhud/p104-gen2-unlock`（Windows 版）

---

## 0. 结论

**在不修改 VBIOS 的前提下，这张卡的 PCIe 链路速率无法从 Gen1 提到 Gen2。**
三条软件路径全部实测失败，其中一条会导致 GPU 掉出总线。

| 路径 | 做法 | 结果 |
|---|---|---|
| ① PCI 配置空间 | `setpci` 写 `LNK_CAP` / `LNKCAP2` / `LNKCTL2` | ❌ 全部只读，写后被硬件丢弃 |
| ② `0x8C040` | 整字写 `SPEED[19:18]=1` + `COMMIT` | ❌ **GPU 掉出 PCIe 总线**，只能重启 |
| ③ 通路 B | `0x8841C[15]=1` + 复位锁存 | ❌ PCI 复位把 `0x8841C` 重置，预置值丢失 |

**根本障碍**：熔丝 `GEN23_DIS=1`（`0x02157C`）、`GEN3_DIS=1`（`0x021580`）——
硬件层面已禁用 Gen2/Gen3，且熔丝只读。

---

## 1. 前置：BAR0 访问

sysfs `resource0` 的 mmap 返回 EINVAL，`/dev/mem` 返回 EPERM（BAR0 被 nvidia 独占，
`CONFIG_IO_STRICT_DEVMEM=y`）。解决：内核参数 `iomem=relaxed`（重启生效）。

```
BAR0 = 0xf6000000 - 0xf6ffffff（16 MB）
```

**注意**：`0xf6000000` 下 `/proc/iomem` 显示 `nvidia` 子项 = 驱动标记独占。

---

## 3. 第二步：`0x2241C` + `0x8872C`（无效果）

```
写 0x2241C = 0x80（仅 bit7）
写 0x8872C = 6
→ LNKSTA 仍 0x1041，LNKCAP2 仍 0x02
```

**两个错误**：
1. `0x8841C[14:13] = 3`（降级门开着），单靠 `0x2241C` 无效
2. `0x2241C` 应为 `0x81`（bit0 `PCIE_VERSION` 也要置 1），不是 `0x80`

---

## 4. 第三步：照抄 Gen2 态（**部分成功**）

```
写 0x8841C = 0xC0B5AD00（参考项目 Gen2 态的值）
写 0x2241C = 0x81
写 0x8872C = 6
→ LNKCAP2: 0x02 → 0x06   ★ 能力声明解锁成功
→ LNKSTA:  仍 0x1041（Gen1）  ← 实际速率没动
```

**这一组操作安全、可重复，不导致掉卡。**

**结论：能力声明（config space 声明支持哪些速率）与实际链路速率是两个独立的东西。**
声明可以靠 `0x8841C` 改成 Gen2，但链路不会因此重训到 Gen2。

---

## 5. 第四步：`0x8C040`（**事故**）

```
写 0x8C040: 0x20085800 → 0x20045801
             （SPEED[19:18]: 2 → 1 = 5.0GT/s，COMMIT=1）
→ 所有寄存器读回 0xffffffff
→ LNKSTA = 0xffff，GPU 掉出 PCIe 总线
→ dmesg: NVRM: RmInitAdapter failed! (0x22:0x56:897)
→ remove + rescan 无法恢复，只能重启
```

**参考项目文档警告的是"逐位写走查会掉卡"，我写的是整字（只改 SPEED + COMMIT），照样掉卡。**
⇒ 该寄存器的危险范围比文档记录的更宽，**任何写都可能致命**。

**推测失败原因（未验证）**：本机 `0x8C040` Gen1 值是 `0x20085800`，
参考项目是 `0x20585800`，**差 bit20 + bit22**。这两位语义未知（可能 N_FTS / lane 配置），
本机缺这两位时写入 SPEED 会触发无效配置 → 链路崩溃。

---

## 6. 第五步：通路 B（`0x8841C[15]` + 复位锁存）

参考项目称"复位前置 1 → 复位后声明锁存为 Gen2，实测 7/7"。

**尝试 A：unbind/bind 驱动**
```
写 0x8841C bit15=1 → 0xc0b4e500（读回确认）
unbind/bind nvidia
→ 0x8841C 仍 0xc0b4e500，但 LNKSTA/CAP2 都没变
```
原因：unbind/bind 只是驱动重新绑定，**不是硬件复位**。

**尝试 B：清降级门 + PCI reset**
```
写 0x8841C = 0xc0b48500（bit15=1，[14:13]=00）
PCI reset（echo 1 > .../reset）
→ 0x8841C 变为 0x00340500（bit15 被清！）
→ LNKSTA 仍 Gen1，CAP2 仍 0x02
```

**⇒ PCI 复位会重置 `0x8841C`，预置值无法存活到复位之后。**
这条机制在本卡上不成立。（参考项目"7/7 成功"与本机结果矛盾，原因未查明；
可能是他所说的"复位"级别不同，或 VBIOS 行为差异。）

**副作用**：PCI reset 后 `0x8841C` 一度变成 `0x00340500`，
但驱动重新初始化后自动恢复为 `0xc0b46500`，GPU 功能完好（`nvidia-smi` 正常、GL 渲染通过）。

---

## 7. 三条路的共同障碍：熔丝

| 熔丝 | 地址 | 值 | 含义 |
|---|---|---|---|
| `GEN23_DIS` | `0x02157C` | **1** | Gen2/Gen3 被禁用 |
| `GEN3_DIS` | `0x021580` | **1** | Gen3 被禁用 |
| `LANE_DIS` | `0x021394` | 0 | 宽度未被禁用 |

参考项目已验证这些是**只读熔丝**（5 份 dump、700 个可读点恒定），
且同类卡（CMP 170HX / GA100）读到完全相同的三值，用安全协处理器级写入也只到 Gen2。

**⇒ 想突破 Gen2，只能改 VBIOS 里的 devinit / 熔丝配置 → 需要写 EEPROM，不可逆，风险极高。**

## 9. 实测收益评估

即使解锁成功，本机收益也有限：

| | 本机 | 参考项目 |
|---|---|---|
| 链路 | **Gen1 x4**（`LNKSTA=0x1041`） | Gen1 x4 |
| 带宽 | ≈0.78 GB/s | 0.78 GB/s |
| 解锁后 | ≈1.55 GB/s（理论） | 1.55 GB/s（实测） |

而本项目此前的研究（报告 116/117）已确认 **GL 渲染的瓶颈不在 PCIe**。
对桌面/GL 场景，0.78 GB/s 已够用。

---

## 10. 建议

1. **停止这条路线**。不改 VBIOS 就无解，改 VBIOS 风险与收益不成比例。
2. 若确实需要更高带宽，考虑换一张不锁速率的卡（如 GTX 1070）。
3. **回滚 `iomem=relaxed`**（若不再做寄存器实验）：
   ```
   sudo cp /etc/default/grub.bak-20261028-221817 /etc/default/grub
   sudo update-grub   # 下次重启生效
   ```

## 12. 第八步：完整配方复现（2026-10-28 晚，第二次尝试）

找到参考项目 §3.2「完整配方（五步缺一不可）」后按原顺序复现。
**此前的失败是因为只做了 8 个动作中的 2 个。**

### 12.1 执行记录

```
第1步 写寄存器（顺序：覆盖槽 → 配置门 → 触发 → 0x8C040）
  0x8E110 覆盖槽0  = 0x00000001  ✓
  0x8E11C 覆盖槽3  = 0x00000004  ✓
  0x8E120 值0      = 0x00000000  ✓
  0x8E12C 值3      = 0x00200000  ✓
  0x8841C cfg      = 0xc0b46500 → 0xc0b42d00   (置 bit11/13，清 bit12/14)
  0x88610 gate     = 0x00000000 → 0x00000001   (清 bit12，置 bit0)
  0x8872C ltssm    = 0x6                        (触发)
  0x8C040 link0    = 0x20085800 → 0x20045801   (SPEED=1 + COMMIT)
     读回 = 0x20045800   ← SPEED=1 生效，COMMIT 位自清
第2步 PnP 禁用→启用（unbind → bind）        ✓ 成功，驱动 408s 重新加载
第3步 等 25 秒                              ✓
第4步 两端设目标速率 + 交替重训
  根端口 LNKCTL2 → 0002                     ✓ 写进去了
  第1~3 轮：设备 ★掉卡（LNKSTA=0xffff）
→ 443s：NVRM: RmInitAdapter failed (0x22:0x56:897)
```

### 12.2 这次学到的两件事

**① 覆盖槽确实起作用了**

上次（未配覆盖槽）直接写 `0x8C040` → **立即**掉卡。
这次先写好 `0x8E110` 系列，再写 `0x8C040` → **写入成功、读回 `0x20045800`（SPEED=1）**，没有立即崩溃。

**⇒ 覆盖槽（XP3G override slot）是 `0x8C040` 写入的前置条件，这一点被证实。**

**② 但链路在真正切换时崩溃**

`0x8C040` 里 SPEED 已经从 2（2.5GT/s）改成 1（5.0GT/s），PnP 复位也完成了，
驱动在 408 秒重新加载成功 —— 然后在 25 秒的等待窗口里（443 秒）初始化失败。

**⇒ GPU 真的按 Gen2 去初始化链路了，但物理层起不来，于是整条链路崩溃、驱动挂掉。**

### 12.3 结论修正

之前写"`0x8C040` 不能写"是错的。准确说法是：

> **`0x8C040` 可以写（配好覆盖槽之后），SPEED 字段也能写进去。
> 但这张卡的物理层只能跑 Gen1，强制设成 Gen2 会让链路在重训时崩溃。**

这从另一面**证实了熔丝 `GEN23_DIS=1` 是真实生效的**——
硬件层面确实禁了 Gen2，不是"只是声明被压着"。

参考项目称同型号卡 0.78→1.55 GB/s 成功，而本机两次失败。
最可能的解释：**卡的生产批次不同**——早期批次物理层支持 Gen2（被 VBIOS 限制），
后期批次物理层就只有 Gen1。VBIOS 版本（`86.04.7A.00.19`）不能区分这一点。

### 12.4 恢复

掉卡后 `unbind/bind`、`rescan` 均无法恢复，**只能重启**（寄存器改动不持久，
重启后回到 Gen1 x4）。

## 13. 第九步：按正确配方重跑（2026-10-28 深夜，第五次）

找到"完整配方"与"状态 L 模型"后，用正确顺序重跑。这次把文档 A 列（Gen2 态）
的每一项都逐一对上了。

### 13.1 逐步验证到的状态

| 步骤 | 操作 | 结果 |
|---|---|---|
| 1 | `0x88610 = 1` | **`EXP_HEAD.VER`: 1 → 2**（设备进入 PCIe v2 模式，约 1s 延迟生效） |
| 2 | `0x2241C = 0x81` | ✓ |
| 3 | `0x8841C`：bit15=1，`[14:13]=0` | ✓ |
| 4 | `0x8872C = 6` | **`LNKCAP2`: 0x02 → 0x06**（声明立刻解锁） |
| 5 | `LNKCTL2 = 2` | **读回 `0x0002`**（VER=2 后不再被钳成 0/1） |

**与文档 A 列（Gen2 态）逐项对比：**

| 项 | A 列 Gen2 | 实测 | |
|---|---|---|---|
| `LNKCAP2` | `0x06` | **`0x06`** | ✅ |
| `0x8841C[14:13]` | 0 | **0** | ✅ |
| `0x2241C` | `0x81` | **`0x81`** | ✅ |
| `EXP_HEAD.VER` | 2 | **2** | ✅ |
| `LNKCTL2` | 2 | **`0x0002`** | ✅ |
| **`LNKSTA`** | **`0x1042`** | **`0x1041`** | ❌ |

**六项对五项，唯独实际链路速率不动。**

### 13.2 所有触发方式都试过，全部无效

| # | 触发方式 | 结果 |
|---|---|---|
| 1 | `0x8872C = 6`（LTSSM） | 声明变 0x06，链路不动 |
| 2 | 根端口 `LNKCTL.bit5`（Retrain） | bit 自清（执行了），链路不动 |
| 3 | **GPU 侧 `LNKCTL.bit5`**（`0x88088`） | bit 自清，链路不动 |
| 4 | **按住 8 秒**：每 20ms 重写 LNKCTL2=2 + LTSSM=6 + Retrain（约 400 次） | 链路不动 |
| 5 | `0x8C040` SPEED+COMMIT | **四次掉卡** |

### 13.3 一个重要的观察：声明会回退

按住停止后，`LNKCAP2` 从 `0x06` **退回 `0x02`**。

⇒ 这解释了文档说的"不按住会掉回 Gen1"——**连"声明"都需要持续施压维持**，
不只是链路速率。但即便如此按住，链路也上不去。

### 13.4 结论

**本卡的 PCIe 声明层完全可改（六项状态全对），但 PHY 物理层只能跑 2.5 GT/s。**

证据强度：这是把文档给出的配方**逐项执行完**之后的结果，不是"试了几下没成"。
六项状态全部对上、五种触发方式全部试过、按住持续 8 秒施压——链路仍停 Gen1。

与熔丝 `GEN23_DIS=1` / `GEN3_DIS=1` 一致。

**与他成功的差异**：最可能是 PHY 硬件批次不同——他的卡 PHY 支持 5GT/s
（只是被 VBIOS 的声明压住），我们的批次 PHY 只有 2.5GT/s 能力。
两者 VBIOS 版本相同（`86.04.7A.00.19`），无法从版本号区分。

### 13.5 系统状态

GPU 功能完全正常（`nvidia-smi` 正常，57.7W / 41°C）。
`0x8C040` 已自动回到 `0x20085800`，`cfg` 回退为 `0xc0b4e500`，链路 Gen1 x4。
**无需重启**（本轮没有掉卡）。
