# 成功配方 vs 我们的失败：差在哪

**日期**：2026-10-28
**来源**：参考项目 `docs/01-技术报告.md` §3.2「完整配方（五步，缺一不可）」+ `docs/02-工具说明.md`

---

## 0. 先回答：PCIe 限制在 VBIOS 里吗

**不在。**

限制在 **GPU 内部的一组「能力生成器输入寄存器」**（`0x8841C` / `0x8E110` 系列 / `0x2241C`），
主机在**运行时可以写**。VBIOS 的作用只是**开机初始化时**把这组寄存器设成 Gen1。

```
VBIOS（初始化一次）→ 把输入寄存器设成 Gen1
                        ↓
                 能力生成器读输入 → 生成 LNKCAP2 = 0x02（只支持 Gen1）
                        ↓
               链路按声明协商 → Gen1 x4
```

**关键**：输入寄存器是 RAM 性质的，运行时改写后可以让生成器重新输出 Gen2。
熔丝（`GEN23_DIS=1`）才是硬件级的墙，但它只挡住 **Gen3**；Gen2 是被输入寄存器"按"在 Gen1 的。

---

## 1. 他的五步配方（原文）

| 步 | 内容 | 要点 |
|---|---|---|
| **1** | 写一组寄存器：<br>`0x8E110=1`、`0x8E11C=4`、`0x8E120=0`、`0x8E12C=0x200000`<br>`0x8841C`：**置 bit11/13，清 bit12/14**<br>`0x88610`：**清 bit12，置 bit0**<br>`0x8872C=6`<br>`0x8C040`：SPEED[19:18]=1 + COMMIT | 先配好 **XP3G 覆盖槽**，最后才动 `0x8C040` |
| **2** | **PnP 禁用 → 启用**（不是"重启设备"） | 让"声明"重新锁存 |
| **3** | **等 ≥ 25 秒** | 等 2 秒锁不住；25 秒才行 |
| **4** | **两端**（GPU + 根端口）都设目标速率 = 2，交替触发重训 | 只写一端不够 |
| **5** | **常驻进程每 ~20 ms 重写**相关寄存器 | **"按住"是必需的**，不按住会掉回 Gen1 |

他文档原话：

> 真正起作用的不是单次写入，而是「**写请求 → 重新初始化 → 等锁存 → 按住**」这一整套时序。
> 这也解释了为什么手工试一次通常失败。

---

## 2. 我们做了什么、漏了什么

| 步 | 他 | 我们 | 差距 |
|---|---|---|---|
| 1a | `0x8E110=1` / `0x8E11C=4` / `0x8E120=0` / `0x8E12C=0x200000` | **完全没碰** | ❌ 缺 XP3G 覆盖槽 |
| 1b | `0x8841C`：置 bit11/13，清 bit12/14 | 写了 `0xC0B5AD00`（整字照抄），另试过 bit15 | ⚠ 值不同、目的不同 |
| 1c | `0x88610`：清 bit12，置 bit0 | **没碰** | ❌ 缺门控位 |
| 1d | `0x8872C=6` | ✅ 做了 | — |
| 1e | `0x8C040` SPEED+COMMIT | ✅ 做了（**掉卡**） | ⚠ 缺前置配置 |
| 2 | PnP 禁用→启用 | 试过 unbind/bind、PCI reset | ⚠ 不完全等价 |
| 3 | **等 ≥ 25 秒** | 只等 **0.5～3 秒** | ❌ 差一个数量级 |
| 4 | 两端都设目标速率 | **只写了 GPU 端**（且被钳回） | ❌ 漏了根端口 |
| 5 | 常驻按住 20 ms | **完全没做** | ❌ 最关键的缺失 |

**8 个动作我们只做对了 2 个。**

---

## 3. 为什么我们会掉卡

我们直接写了 `0x8C040`（SPEED + COMMIT），**但没先配置 XP3G 覆盖槽**（`0x8E110` 系列）。

他文档 §4 危险清单里写：

> 对含 COMMIT / 使能 / 复位语义的寄存器做逐位写走查 → 显卡掉下 PCIe 总线

我们的情况更糟：**覆盖槽是空的（未配置），直接触发 COMMIT** → GPU 拿一组无效参数去重训链路 →
链路崩溃 → 设备掉出总线。

**⇒ 不是"0x8C040 不能写"，而是"没配好前置条件就写会崩"。**

---

## 4. 在 Linux 上复现的路径

| 他的动作 | Linux 等价物 |
|---|---|
| 写寄存器 | `/dev/mem` + mmap BAR0（需 `iomem=relaxed`）✅ 已具备 |
| 两个内核驱动访问 MMIO | 不需要，Linux 直接 mmap |
| PnP 禁用 → 启用 | `unbind` → `bind`（或 `remove` → `rescan`） |
| 等 25 秒 | `sleep 25` |
| 两端设目标速率 | GPU：`setpci` 写 `LNKCTL2`（被钳回）；根端口 `00:01.0`：可写 |
| 常驻按住 20 ms | 后台进程循环重写 |

**全部可行，且我们已经打通了最难的 BAR0 访问。**

---

## 5. 剩余风险（必须说清）

| 风险 | 说明 |
|---|---|
| 再次掉卡 | 概率不低。但用户已确认"核显输出，掉卡无影响" |
| 需要"按住"进程常驻 | 意味着**开机要跑服务**，否则重启后回到 Gen1 |
| 每 20 ms 写 MMIO 的副作用 | 未知。他跑通了，但长期影响没数据 |
| 收益 | 0.78 → 1.55 GB/s（x4），而 GL 渲染瓶颈不在 PCIe |

---

## 6. 一句话总结

**我们不是"方法不对"，而是"只做了 2/8 步就写最危险的那一步"。**

他那句"缺一不可"是真的：XP3G 覆盖槽、25 秒等待、两端同设、20 ms 按住，
这四个环节我们全漏了。补上之后仍有成功可能。
