# 失败的实验（保留作历史，不要当成可用工具）

## `test-declare-heal.sh`
**目的**：验证"守卫能否自己把被重置的声明补回来"。

**背景**：实测 `rmmod nvidia && modprobe nvidia` 之后，驱动会把端点重置回 Gen1：
```
LnkCap.MaxSpeed = 1     LnkCap2 = 0x0002     LnkCtl2.TLS = 1
```

**做法**：给 gen2kr 的守卫加三步自愈 —— ① 重写端点 TLS=2 ② 重写根端口 TLS=2
③ 重新解锁声明 + 触发训练。

**结果：无效，已回滚。**

| 检查项 | 结果 |
|---|---|
| 写 TLS=2 后再读 | 下一轮又读到 `0001`（被驱动钳住，抢不过） |
| 重新解锁声明 + 触发训练 | `CAP2` 始终 `0x0002` |
| `unbind/bind` ×6 + 解锁 ×9 | 链路始终 `LNKSTA=1` |

而且每 600ms 猛写配置空间本身有风险 ⇒ 回滚。

**正确做法**：整机重启。重启后第一次 push 就成功。

这说明"前置条件被驱动重置"这种情况**不能靠软件抢**，只能重启回到干净状态。
