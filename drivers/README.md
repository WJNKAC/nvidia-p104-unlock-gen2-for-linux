# 按驱动版本组织的补丁

每个子目录对应**一个 NVIDIA 驱动版本**，里面是那个版本上验证过的全部补丁。
思路参考 [vGPU-Unlock-patcher](https://github.com/VGPU-Community-Drivers/vGPU-Unlock-patcher)
的 `patches/blob-<version>.diff` 约定：**偏移和字节都跟版本绑定，不能跨版本套用**。

## 为什么按版本分目录

补丁改的是**闭源二进制的具体字节**。换一个驱动版本：

- 函数位置会变（`nvidia.ko` 里 `.text` 偏移变）
- 甚至代码结构会变（`libnvidia-glcore.so` 里判据偏移会变）
- md5 完全不同

所以每个版本都要**重新定位、重新验证**，不能复用别的版本的数字。
把「版本 → 偏移 → 验证数据」固定在一个目录里，是唯一不会搞混的做法。

## 目录约定

```
drivers/<驱动版本>/
├── README.md      这个版本的简介：有哪些补丁、偏移表、验证数据、风险
├── offsets.sh     机器可读的偏移（可被 source，也可直接看）
└── minimal.sh     最小实现：check / apply / revert（自包含，零仓库依赖）
```

`minimal.sh` 是**独立可用**的：把它和驱动文件放一起就能跑，不需要克隆整个仓库。
它只是「最小复现」，完整流程（推送、验证、长跑）仍用仓库根目录的 `bin/`。

## 三个补丁分别解决什么

它们解决的是**三个不同的问题**，可以单独用，也可以叠加：

| 补丁 | 解决 | 症状 | 改哪个文件 | 改动量 |
|---|---|---|---|---|
| **Gen2** | PCIe 链路速率 | `0.78 GB/s`（Gen1 x4） | `nvidia.ko` | 2 字节 |
| **delay** | gr3d 每批次延迟 | 帧率卡 ~40fps，功耗上不去 | `libnvidia-glcore.so` | 1 字节 |
| **whitelist** | 驱动的「受限 SKU」判定 | 同 delay（但这是**上游源头**） | `nv-kernel.o_binary` | 10 字节 |

### delay 与 whitelist 的关系（★ 别同时用）

实测（reports/174 / N185）：

| 配置 | 帧时间 | fps | 命令是否生成 |
|---|---|---|---|
| 都不打 | 52.202 ms | 18.98 | 40+ 条 |
| **只打 whitelist** | **3.668 ms** | 243.78 | **0 条** |
| 只打 delay | 3.434 ms | 259.79 | 0 条 |
| 两个都打 | 3.667 ms | 246.64 | 0 条 |

⇒ **只打 whitelist 就够了**，delay 补丁在它之上没有额外收益。
whitelist 是「命令根本不生成」，delay 是「生成了但跳过」——前者更彻底。

但 whitelist 要重建内核模块（较麻烦、需要重载驱动），delay 只改用户态文件（重启程序即可）。
**只想快速见效就用 delay；想彻底解决就用 whitelist。**

## Gen2 的额外要求

Gen2 的 2 字节补丁只做到「驱动不再把速率降回 Gen1」，
**链路本身还需要有人推上去**（解锁端点声明 + 写 SPEED + 重训）。

推送由 `kmod/gen2kr.c` 完成（在 `nv_pci_probe` 返回瞬间做），
完整流程见仓库根目录的 `README.md`。`minimal.sh` 只管那个 2 字节补丁。
