## 真差在哪：不是技术，是**平台**

你的方案三步依赖 Windows 专有能力：

| 你的步骤 | Windows 实现 | Linux 有没有等价物 |
|---|---|---|
| 第 2 步 让声明重新锁存 | **PnP 禁用/启用**（设备级重初始化） | ❌ 没有。`unbind/bind` 不重置；`remove/rescan` 会被驱动 reprobe 重置回来；reload nvidia 也不重置（我们实测） |
| 第 3 步 等 ≥25 秒 | 等驱动重新绑定 + 读注册表 | ⚠ 概念能对上，但 Linux 这边没人验证过这个窗口 |
| 第 5 步 每 20ms 按住 | WinRing0x64.sys 内核驱动直接写 BAR0 | ⚠ **能做但危险**：用户态 mmap 写 BAR0 在链路动态时我们 2/2 打挂设备（ZOMBIE，只能重启）。内核 writel 才安全 |

所以你说「Linux 下原理一样」——**原理一样，但第一根支柱没有**。

## 我们的绕法：不去锁存，改成让驱动别降级

既然 Linux 上没有「PnP 重初始化让声明锁存」这一步，我们换了思路：

```
① 2 字节补丁：_nv017105rm 的 mode 白名单 {1,2,3} → {2,3}
   （lea -0x1 → -0x2, cmp $0x2 → $0x1；mode==1 下溢走原有 bail，
     返回 %r12d=0=CUDA_SUCCESS，驱动认为成功）
   ⇒ 驱动不再在每次 cuInit 时降级

② kretprobe 挂 nv_pci_probe，在返回瞬间 live 写入 + 重训 → 链路升 Gen2
```

关键差别：**你的第 5 步「按住」我们不能做（每 20ms 写 BAR0 太危险），
所以改成「让驱动别降」——补丁之后就不需要按住了。**

实测：353 轮 CUDA 上下文零降级、Xid 0、pinned 1.56/1.71 GB/s。
