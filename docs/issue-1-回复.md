# Issue #1 回复 —— 核查后定稿

---

先说清楚：我们已经在 Linux 下做成了（上面那个仓库），所以只针对你给的三步逐条对一下。

**第一步：`lspci -vv` 看 `LnkCap2` bit1**

这里有个更基础的问题：**标准 PCIe 规范里 `LnkCap2` 的 SLSV 字段就是 bits[7:1]**，
`bit1 = 2.5GT/s`、`bit2 = 5.0GT/s`、`bit3 = 8.0GT/s`（bit0 保留）。
所以「看 bit1 是否为 1」判断不了 5.0GT/s —— **bit1 在所有设备上恒为 1**，它表示的是 2.5GT/s。

我们卡上实测可以印证这个偏移（根端口声明 Gen1~Gen3）：

```
根端口 LnkCap2 = 0x0e = 0b1110  →  bits{1,2,3}  →  lspci 报 "2.5-8GT/s"   ✓
我们的卡 LnkCap2 = 0x02 = 0b10  →  bits{1}      →  只有 2.5GT/s
解锁后     0x06 = 0b110 →  bits{1,2}    →  2.5 + 5.0GT/s
```

所以该看的是 **bit2**。我们卡出厂就是 `0x02`，压根没声明 5.0GT/s（你报告 §1.2 也是这个值）。

⇒「如果声明了 5GT/s 但停在 2.5GT/s」这个前提在我们这里不成立。真正要做的是先把声明打开，
这得写 NVIDIA 私有 BAR0，`setpci` 够不到。

**第二步：`LnkCtl2` 低 4 位写 2**

这一步单独做没用，会被硬件钳回。

依据是你自己 §4.1 的实验：声明 `0x06` 时写 `LnkCtl2=3` → 读回立刻是 2，4527 次全被钳。
说明硬件把 `LnkCtl2` 钳到**声明的上限**。声明还是 `0x02` 时，上限是 1，写 2 应该会被钳回 1。

（这条是**推断**，不是我们实测的 —— 我们没在声明 `0x02` 的状态下单独试过写 `LnkCtl2`。
不过下面那个"原样跑你脚本"的提议可以把这个补上。）

**第三步：`remove + rescan`**

- **对速率没用。** 声明没解锁，rescan 只是重新枚举，`LnkSta` 不会变。
- **`remove` 本身是安全的。** 我们实测健康设备 `unbind → remove → rescan`，0.5 秒回来、
  `power_state=D0`、无事故。
- 但要注意：如果设备已经因为写错寄存器**掉卡了**（`cfg=0xffffffff`），
  这时候 `remove`/`rescan`、次级总线复位**都救不回来**，只能整机断电。
  （踩过：写 `0x8C040` 的 COMMIT 位时没有前置步骤，设备直接离开总线）

**另外，就算前两步成功，链路也保不住**

**NVIDIA 驱动每次 `cuInit` 都会主动把速率降回 Gen1**：

```
rm_init_adapter+0xcd → _nv017755rm → _nv017105rm(mode=1) → 写 0x8C040.SPEED=2
```

perf 硬件断点实测 4/4 次都以 `mode=1` 进这个函数。这条在你「待确认」清单里，答案是「会」。

**所以 Linux 上要加两步**

1. **解锁声明**（写 BAR0，`setpci` 做不到）

   ```
   0x8E110 = 0x00000001    0x8E11C = 0x00000004
   0x8E120 = 0x00000000    0x8E12C = 0x00200000
   0x8841C = (读值 | bit11|bit13|bit15) & ~(bit12|bit14)     ← 必须读-改-写
   0x88610 = (读值 & ~bit12) | 1
   0x8C2C0 : 清 bit2（DIS_G2）
   0x8872C = 6              ← 触发训练，声明当场锁存成 0x06
   ```

   **这步不需要复位，也不需要 PnP** —— 写完 `0x8872C` 后 `LnkCap2` 立刻变 `0x06`。
   你 Windows 那套 PnP + 25 秒是为了绕开驱动把位压回去，不是硬件必需。

2. **让驱动别降**。我们是给 `_nv017105rm` 打了 2 字节补丁
   （`lea -0x1`→`-0x2`、`cmp $0x2`→`$0x1`，让 `mode==1` 走原有 bail、返回 `CUDA_SUCCESS`），
   比「每 20ms 按住」省事得多 —— 补丁之后不需要任何人按住。

**顺便提一下你 README 的输出示例**

`LINKCAP2 = 0x00000006` —— 但脚本里 grep 不到任何写 `0x8841C` / BAR0 的地方。
既然脚本做不到解锁声明，这一步不可能读到 `0x06`，那段应该是从 Windows 版输出粘过来的。
