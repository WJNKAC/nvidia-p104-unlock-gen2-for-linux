# BAR0 寄存器参考（P104-100 / Pascal）

> 全部偏移相对 BAR0（本机 `0xf6000000`）。
> 完整地址 = BAR0 + 偏移。用户态读：`mmap("/dev/mem", ..., offset=BAR0)`。

## 判据类（只读）

| 偏移 | 名称 | 关键字段 | 用途 |
|---|---|---|---|
| `0x88084` | LNKCAP 镜像 | `bits[3:0]` MaxSpeed | 端点声明的最大速率 |
| `0x880A4` | **LNKCAP2 镜像** | `bits[7:0]` 支持向量 | **`0x06` = 已解锁支持 Gen1+Gen2；`0x02` = 仅 Gen1** |
| `0x88088` | **LNKSTA 镜像** | `bits[19:16]` CurSpeed | **`2` = Gen2，`1` = Gen1 ← 唯一可信的"当前速率"判据** |
| `0x880A8` | LNKCTL2 镜像 | `bits[3:0]` TLS | 目标速率（`2` = 5.0GT/s） |
| `0x8C040` | LINK_CONFIG_0 | `bits[19:18]` SPEED | Pascal：`1`=5GT/s，`2`=2.5GT/s，`0`=8GT/s |
| `0x8C2C0` | CYA_0 | `bit2` DIS_G2 | 1 = 禁用 Gen2 |

### config space 对照（`setpci`）

```bash
setpci -s 01:00.0 CAP_EXP+0x0c.l   # LnkCap  ｜ MaxSpeed = bits[3:0]
setpci -s 01:00.0 CAP_EXP+0x2c.l   # LnkCap2 ｜ 支持向量 = bits[7:0]
setpci -s 01:00.0 CAP_EXP+0x12.w   # LnkSta  ｜ CurSpeed = bits[3:0]
setpci -s 01:00.0 CAP_EXP+0x30.w   # LnkCtl2 ｜ TLS = bits[3:0]
```

**正常解锁后的值**（供对照）：

| 寄存器 | Gen1（原厂） | Gen2（解锁后） |
|---|---|---|
| `LnkCap` | `0x00453c41` MaxSpeed=1 | `0x00454c42` MaxSpeed=2 |
| `LnkCap2` | `0x00000002` | `0x00000006` |
| `LnkSta` | `0x1041` | `0x1042` |
| `LnkCtl2` | `0x0001` | `0x0002` |
| `0x8841C` | `0xc0b48d00` | `0xc0b4ad00` |

## 写操作类

### 声明解锁（"从不掉卡"，可按需重做）

| 偏移 | 写入值 | 说明 |
|---|---|---|
| `0x8E110` | `0x00000001` | XP3G_OVR0 |
| `0x8E11C` | `0x00000004` | XP3G_OVR3 |
| `0x8E120` | `0x00000000` | XP3G_VAL0 |
| `0x8E12C` | `0x00200000` | XP3G_VAL3 |
| `0x8841C` | **读值再 OR** `(v \| 1<<11 \| 1<<13 \| 1<<15) & ~(1<<12 \| 1<<14)` | PRIV_MISC_1 ← ⚠ 绝不写绝对值 |
| `0x88610` | `(v & ~(1<<12)) \| 1` | VSEC_HIERARCHY |

`0x8841C` 写好后 **`0x880A4` 不会立刻变**，必须触发一次训练（下面）才锁存成 `0x06`。

### 触发训练 + 切换速率

| 偏移 | 值 | 说明 |
|---|---|---|
| `0x8872C` | `0x6` | 触发 LTSSM 训练（⚠ **驱动从不访问这个寄存器**，见下方警告） |
| `0x8C040` | `(v & ~0x000C0000) \| (1<<18)` | SPEED=1 → 5.0GT/s |
| `0x8C040` | `(v & ~0x000C0000)` | SPEED=0 → 8.0GT/s |

### 根端口（`00:01.0`）

```bash
# TLS = 5.0GT/s
setpci -s 00:01.0 CAP_EXP+0x30.w=$(printf '%04x' $(( ($(setpci -s 00:01.0 CAP_EXP+0x30.w | sed 's/^0x//' | tr -d '\n' ; echo 0x0) ) ))
# Retrain Link（⚠ 只从根端口发，绝不碰端点）
setpci -s 00:01.0 CAP_EXP+0x10.w=0060
```

## ★ 三条必须记住的

### 1. `0x8872C` 是我们从参考项目抄来的，驱动零引用
`.text` 里 `mov $0x8872C` 命中 **0 处**。驱动从不碰它。
实测"写 6 + 根端口 Retrain"确实能触发训练，但这是一个**无文档、无参照的私有开关**，
时序行为不可预测是必然的。用它，但别指望有可对照的驱动行为。

### 2. `0x8C040.bit0` = COMMIT，别从垃圾值派生
```c
lk = readl(0x8C040);                        // 重训瞬态常读到 0xffffffff
writel((lk & ~0xC0000) | (1<<18), ...);
//     0xFFFFFFFF & ~0xC0000 = 0xFFF3FFFF
//     0xFFF3FFFF | 0x40000  = 0xFFF7FFFF   ← bit0=1 = COMMIT → 掉卡
```
**写回前双校验**：① `lk != 0xffffffff` ② `(lk & 1) == 0`。只判第 1 条不够。

> 但注意：COMMIT 本身**不是毒药** —— 驱动自己在 `_nv017105rm+0x1ff` 就会
> `or $0x1,%r15d` 后写回（前面还有回读轮询的前置序列）。
> 致命的是**缺前置步骤就写**。外部仍不要写。

### 3. 用户态 mmap 写入在链路动态时会打死设备
实测 2/2 掉卡（C. ZOMBIE，`dmesg` 无 Xid）。同一操作走内核 `writel` 则几十次无事故。
⇒ **链路控制类寄存器必须走内核路径。**

## 能力位（驱动内部，非寄存器）

不在 BAR0 里，在 RM 的对象结构里：

| 偏移 | 含义 |
|---|---|
| `obj+0x954` | cap Gen2（`_nv017105rm(mode=2)` 的门禁） |
| `obj+0x955` | cap Gen3（`_nv017105rm(mode=3)` 的门禁） |
| `obj+0x956` | cap mode4（仅 `_nv017102rm` 支持） |
| `obj+0x957` | cap mode5 |

由 `_nv017812rm(dev, obj, flags)` 按位标志设置：
`flags & 0x04 → 0x954`、`& 0x08 → 0x955`、`& 0x10 → 0x956`、`& 0x20 → 0x957`。

`flags` 来自 `_nv017279rm` 的**五路能力按位与**
（1 个直接调用 + 4 个 vtable 槽 `obj+0x1a8/0x1b0/0x1b8/0x1c0`）。
任何一路缺 `0x04` 位，Gen2 能力就被清掉。

> `obj+0x954` 的**运行时实际取值仍未拿到**（需要在冷启动后首次 modprobe 时抓，
> reload 之后已错过时机）。这是唯一还没闭环的点。
